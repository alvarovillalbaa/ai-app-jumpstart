The remote suite requires `DATA_PROVIDER=postgres`, `supabase` or `convex` and matching environment variables; missing configuration fails, rather than skips. Each case uses random tenants and deletes its own reference records. Session ownership cases retain tombstones and nonce receipts intentionally; use disposable databases. Never target production. The PostgreSQL harness also checks the read-only migration dry run before applying schema and again after an idempotent rerun, then verifies both modes reject a ledger migration absent from this checkout.

The PostgreSQL CI job runs `db:types:check:ci` after applying migrations to its disposable PostgreSQL 17 service. That mode accepts only a loopback `DATABASE_URL`; it compares the pinned CLI's generated public types with the committed file without starting a second Supabase stack. A local comparison against plain PostgreSQL 17 produced the same public-schema types as the migrated Supabase project. The seed CLI test checks sequential rerun idempotence, owner isolation, changed-content refusal and remote-write opt-in; a live local Supabase-backed app also created two fixtures on the first run and zero on the second.

Run providers individually with `test:postgres`, `test:supabase` or `test:convex`. The PostgreSQL harness uses a temporary native cluster and runs migrations twice. The Supabase harness adds pinned, checksum-verified PostgREST and short-lived local JWTs, and checks that anonymous and authenticated roles cannot read or insert directly. It also models a Storage schema with a deliberately broad policy and verifies that the restrictive policy still denies reads and writes to the quarantine bucket. This SQL model is separate from the optional live Storage API suite. Its local proxy only maps the Supabase REST path; authorization and SQL execute in the real services. The shared upload-catalog contract checks atomic per-owner quota, state transitions, idempotency and isolation on PostgreSQL, Supabase PostgREST and Convex. The shared budget contract checks settled-cost correction and audit isolation on all providers; SQL providers also test that direct UPDATE and DELETE of a correction row fail, and the SQLite operator CLI test checks the same. Convex uses a separate temporary anonymous deployment and also checks that internal functions cannot be invoked through the public query API. These checks clean up their temporary services and do not configure a hosted account. CI runs provider tests, a separate PostgreSQL 17 service contract, the record container contract, the two-database Workflow Compose contract and a credential-free Vercel service-graph build on the runner's native architecture. See [delivery status](DELIVERY.md) for the verified revision and remaining hosted checks.

The accessibility tests use axe-core on actual rendered Chromium pages and include the enabled account/chat state, not just static markup. They catch machine-detectable issues, including missing headings, labels, landmarks and contrast failures. Manual screen-reader, keyboard-flow and cognitive-accessibility review remains necessary before release.

The record container test creates random fixture credentials and a temporary named volume, then removes its container and volume. Use `-- --skip-build` with `TEST_CONTAINER_IMAGE` to check an already built image. The full build can leave a large dangling intermediate image and needs enough Docker VM space for both the build and runtime layers; if it fills the VM, remove only this template's identified disposable build stage before rerunning the contract against the completed image. The separate chat container test compiles the deterministic Eve fixture, copies its output into the running image, and runs the eleven browser contracts against real disposable Supabase Auth/PostgreSQL/SMTP. It tests owned turns and the hosted-account smoke without changing the production model in source. Neither test proves a paid production-model call or cloud deployment.

The Workflow Compose test uses the repository's three Compose files plus a temporary override to select the PostgreSQL Workflow image, a free loopback port and fixture credentials. It leaves `.env.local` alone, verifies every source application migration is recorded and the outstanding-budget index exists, checks the Workflow schema, recreates only the app container, then confirms the same PostgreSQL-backed record and Eve health. It removes its own project and volumes afterward. Use `-- --skip-build` with `TEST_WORKFLOW_IMAGE` to reuse a built image. To test the cloud recipe's Linux amd64 target locally, build with `docker buildx build --platform linux/amd64 --build-arg EVE_WORKFLOW_PROVIDER=postgres --load -t ai-app-jumpstart:workflow-postgres-amd64-test .`, inspect the image architecture, and run `TEST_WORKFLOW_IMAGE=ai-app-jumpstart:workflow-postgres-amd64-test npm run test:workflow-compose -- --skip-build`; see [cloud container preparation](cloud-containers.md#shared-release-preparation). An ARM host needs amd64 emulation and sufficient Docker VM memory. This local check does not prove an owned Workflow turn, multi-instance rollout or cloud ingress.

Playwright uses its own production server at 127.0.0.1:3137, a fixture-only key and `.data/e2e.sqlite`. It does not reuse another server. Never provision fixture keys in an external deployment. Failure traces may contain test data.

The deterministic eval fixture lives in `tests/fixtures/eve`. It imports production arithmetic code and the same four behavior eval definitions available to the live model. It also exposes the production `create_artifact` tool, so the quoted-instruction case checks non-use of an available side-effecting tool. Fixture-only evals exercise anonymous artifact denial, cancellation of a blocked tool turn, rejection of malformed typed tool input before execution, and bounded retry followed by failed turns for scripted 429/503 model errors. The division-by-zero case asserts the real arithmetic tool's explicit error; the unavailable-data and quoted-instruction cases use scripted fixture responses, so they do not establish production-model judgment. Run `npm run eval:live` only with deliberately budgeted provider credentials to test the unchanged model. The separate `tests/fixtures/eve-access` fixture imports the production broker, route policy and ownership/budget hook. Its harness uses random fixture tokens, a forced local Node build target and a fresh temporary app/queue namespace to prove recovery, ownership and runtime budget enforcement. Model calls are counted to verify denied operations do not execute. `test:chat` additionally uses that fixture model with the production channel and real Supabase Auth, through the browser and application broker. Mock models remain confined to fixtures; the production model is unchanged and Eve's default tools are disabled in favor of the authored set. These fixtures do not prove broad quality, hosted identity or reviewed provider pricing.

For new adapters, reuse `recordContract`, `sessionAccessContract`, `budgetContract` and `cancelStartContract`. These cover ownership, concurrency, revocation, replay, atomic usage limits and the cross-store cancellation/binding race. Budget tests include idempotent settlement, unknown costs, overages, rate windows, pending runs across midnight and durable attempt caps. Separate signing and authorization tests cover tampering, key rotation, time bounds and session routes. The runtime fixture proves creation recovery and budget enforcement; reviewed provider pricing remains unfinished. For new tools, keep pure operations testable and add a real runtime eval. For new UI behavior, test user-visible success and failure rather than implementation snapshots. CI is an authored workflow until a remote run confirms it; local checks do not prove cloud acceptance.

The scoped `ansi-to-react` override pins patched `linkify-it` 5.0.2. Rendering tests cover escaped HTML, ANSI color and fuzzy links; major version 6 changes the API and is incompatible with this consumer. Run these tests and the dependency audit when changing the override.

The shared session-access contract also checks history pagination, private control-field exclusion, owner/tenant isolation, pending cancellation versus binding, concurrent rename winners, stale revisions, archive/restore without session revocation, and malformed filters/titles. The cross-store cancellation contract tests a budget-only orphan and an active binding race on all four providers. Separate local tests exercise legacy SQLite and Convex metadata upgrades. History DOM tests cover account changes, late pages, archive-filter races, refreshed credentials, conflict errors, pagination and pending-cancellation success/conflict. The account-chat browser suite pauses the real receipt hook before binding, cancels through the production API, checks a zero-cost release and waits for a failed turn without a model call. It also seeds a budget-only row in its disposable ledger and verifies browser cancellation, owner isolation and blocked replay.

Conversation access tests use the real SDK client over stateless MCP HTTP plus CLI requests through shared REST handlers. They verify the same revisions and owner boundaries, record-key denial despite matching owner strings, disabled-feature handling, revocation, malformed edits and resource redaction. The account-chat harness additionally repeats MCP/CLI/REST metadata interoperability against real Supabase Auth and the compiled application.

Projection contracts verify duplicate ingestion, content conflicts, wrong-session and foreign-owner denial, revoked bindings, ingestion-index pagination, late events with older source IDs, durable source-index annotation/collision handling, and owner/session-scoped checkpoint compare-and-swap across four providers. Recovery unit tests cover finite replay, matching captured events, the 250-event boundary, partial database failures, durable resume and safe retries. The source-order reader test covers filtered events, exact absolute cursors despite reverse event IDs, malformed upstream data and owner denial. Production chat tests check server capture before recovery, then replay the same events without duplicating rows and verify their new indexes; the real-account browser contract blocks recovery, reloads the owned chat, and checks automatic catch-up plus REST, CLI and MCP recovery access. Canonical attempt attribution, unattended recovery and hosted retention are not covered.

The structured-output browser contract uses Eve's real `final_output` protocol with a deterministic fixture. It checks the editable fields, reload from private projections, an accepted request whose browser response is lost, one dispatch, foreign-user denial and rejection of caller-supplied schemas. Broker/budget tests verify both reservations hash the identical signed runtime body.

The artifact provider contract runs against SQLite, PostgreSQL, Supabase PostgREST and Convex. It checks concurrent same-call idempotency, changed-input conflict, owner/session binding, pagination, read-after-revoke, deletion and blocked replay. The browser contract exercises Eve's real approval pause and continuation, checks that no artifact exists before approval or after denial, then reads and downloads the approved artifact and erases the saved copy. Separate CLI and MCP tests check their deletion paths. Runtime budget tests cover the synthetic approval continuation, which Eve emits without `turn.started`.
