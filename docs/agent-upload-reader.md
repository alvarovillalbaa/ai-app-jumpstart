# Read a reviewed upload in chat

The optional native Eve tool `read_upload_text` lets an active registered conversation owner ask the agent to read a specific reviewed UTF-8 upload. It uses the same extraction service as REST/CLI/MCP, then checks the conversation binding and unchanged review again. It cannot enumerate uploads, approve processing, fetch a supplied URL or read another account's object path.

Enable `UPLOAD_AGENT_POLICY=reviewed-text` on the **Eve worker**, with the same private upload metadata/object backend as the web app. The worker also needs `UPLOAD_DOWNLOAD_POLICY=scan-on-read`, a configured `clamd` or `remote` scanner and private `local` or `supabase` object storage. Vercel/Lambda require a remote scanner and remote storage; the managed Vercel preflight additionally requires enabled account chat. Configure the same policy on the web service to show references in the registered upload workspace and the chat picker. Unset or `off` omits the tool and picker. Incomplete/unknown enabled policy fails closed. Account authorization and the production model/Gateway routing remain unchanged.

On `/uploads`, approve an eligible text file for processing. In an owned chat, select **Choose reviewed file**, choose a clean UTF-8 text file of at most 32 KiB, and select **Use file**. The picker verifies the current processing receipt. Write a request such as “Summarize this file.” You can remove the reference before sending; it is not retained for the next request. Submission rechecks the exact review revision and digest. A failed check preserves the request draft and does not dispatch a conversation. No object bytes, extraction or automatic agent turn are requested by the picker. Its requests abort when the chat unmounts, including account changes.

The plain-text Eve transport stores a versioned JSON envelope `{format:"jumpstart.reviewed-upload-message.v1",text,upload:{id,sha256,reviewRevision,name}}`. The full envelope must fit the existing 32,000-character message limit; it is never truncated. User messages display the request and a plain escaped filename/review chip, including after reload. Assistant messages and malformed/unknown envelopes are not treated as references. The conversation title derives from the request while the exact signed transport/hash is preserved. The filename is presentation data and grants no authority. Under **Use this reviewed file in chat** on `/uploads`, copying the strict `{id,sha256,reviewRevision}` reference into a manual request also remains supported.

Selecting or pasting a reference does not authorize reading. The typed tool displays the three exact reference arguments and pauses for native Eve approval **before every call**. The metadata approval check reads no object bytes and does not invoke the scanner. A foreign responder cannot approve the request.

After approval, the executor rechecks the trusted initiator/current caller and the exact active application operation/session binding. It requires the same approved digest/review revision, then checks stored size/type/hash, obtains a fresh malware verdict, and rechecks the conversation and current receipt before returning at most **32 KiB in raw UTF-8 bytes**. Changed consent, rejected/deleted files, revoked conversations, unsupported content or scanner failure return a generic error without file text. Refresh the review and request a new call after a conflict; a stale approval cannot widen authority. The agent never receives write/review authority from this reader.

The result carries the exact upload ID, SHA-256, review revision, `text/plain` type and `trust:"untrusted-user-content"`. Instructions require the agent to treat the text as source data and ignore embedded attempts to change permissions or use tools. The framework's provider middleware counts tool results inside the SDK input envelope before each provider call; existing model-call/output/input caps still apply. No truncation or automatic ingestion occurs. Paid-model behavior, reviewed prices and exact provider input-token enforcement remain separate release acceptance.

**Retention changes when the native read succeeds.** The text becomes a tool result in Eve/model history and can appear in owned stream projections, assistant replies, application-visible exports, provider processing and stopped-service backups. The application does not create embeddings or a separate extraction cache, but runtime replay can reuse an already returned result. Revoking processing consent or deleting the upload fences later reads; it cannot recall text already returned, erase conversation/runtime/provider copies or certify account-wide erasure. Native approvals authenticate the submitting account, not the physical presence of a human. Review provider retention and coordinated conversation/account deletion before production activation.

This is an explicit reviewed-file reference picker and reader. The composer still rejects direct raw attachments; binary/PDF/image extraction, asynchronous document ingestion, embeddings, versioned retrieval and coordinated deletion remain open. Default installations keep the reader absent.

`npm run test:agent-uploads` compiles the production tool and ownership hooks with an isolated app/Workflow namespace and a deterministic model. It verifies no private text before approval, denied calls, a second call requiring a new approval, foreign uploads/responders, revocation/rejection while an approval is parked, scanner outage and exact Unicode/newline text delivered with the trust marker. Root service tests additionally revoke the conversation during a paused scan. The scanner fixture speaks real INSTREAM framing but does not detect malware; the existing real ClamAV tests cover its separate engine boundary. CI runs this rehearsal. Hosted worker/storage/scanner acceptance and a paid production-model turn remain unverified.

`npm run test:chat:uploads` provisions real disposable Supabase Auth accounts, production Next and compiled Eve with the production channel, private SQLite/object storage and the same protocol scanner fixture. Its browser contracts cover selection, native approval, exact Unicode/newlines, reload, a second read requiring another approval, foreign responders/uploads, pre-submit and parked revocation, retained drafts, escaped filenames and automated accessibility. It needs `build:local`, Chromium and Docker, and runs separately from the reader-off account/container suites. This is local real-account acceptance with a deterministic model, not hosted storage/scanner or paid-model proof.
