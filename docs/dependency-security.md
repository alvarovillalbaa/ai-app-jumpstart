# Dependency security gate

`npm run check:dependencies` runs `npm audit --audit-level=high`. The gate permits moderate and low advisories under that threshold and fails on unexpected high or critical advisories.

One exact exception is tracked for `brace-expansion@5.0.9` bundled inside the dev-only `aws-cdk-lib@2.271.0` dependency. The current audit identifies three advisories for that bundled copy: [GHSA-q2hr-2g5m-vwhr](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr), [GHSA-qhr7-859c-m2p7](https://github.com/advisories/GHSA-qhr7-859c-m2p7) and [GHSA-6j4f-fj2g-mc7p](https://github.com/advisories/GHSA-6j4f-fj2g-mc7p). The gate accepts them only at the exact lockfile path, package versions and advisory set. AWS CDK documents that consumer overrides cannot replace dependencies bundled inside `aws-cdk-lib`; the fix must arrive in an upstream package bundle ([AWS CDK issue](https://github.com/aws/aws-cdk/issues/38496)).

Remove the exception when the selected AWS CDK release bundles a `brace-expansion` version outside the affected advisory ranges. The gate will fail automatically if the CDK version, bundled path, brace-expansion version, audit range or advisory set changes.

## Automated updates and code scanning

[Dependabot](https://docs.github.com/en/code-security/dependabot) checks the root and `my-agent` npm lockfiles, the root and `deploy` container definitions, and GitHub Actions weekly. Minor and patch npm updates are grouped by production and development dependencies; major upgrades remain individual updates. Version-update configuration is read from the default branch, so these checks become active after this file reaches `main`. Repository Dependabot settings can also disable version updates independently.

[CodeQL](https://docs.github.com/en/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning-with-codeql) runs the high-precision default suite for JavaScript/TypeScript and GitHub Actions on pull requests, pushes to `main`, and a weekly schedule. A separate [`CodeQL Extended` workflow](../.github/workflows/codeql-extended.yml) runs GitHub's `security-extended` suite manually or weekly, with its own analysis category; the suite includes the default queries plus additional queries with lower precision and severity, so it may produce more false positives. Treat those findings as a review queue, check each against current source, and do not dismiss a baseline wholesale. Both workflows upload code-scanning results; repository settings must allow Actions workflows to upload them. Findings appear as code-scanning alerts and in the pull-request summary for triage. Repository rules determine which checks are required before merging. GitHub requires a workflow file on the default branch before its `workflow_dispatch` and scheduled triggers are available; this PR's `CodeQL Extended` workflow is not yet on `main`.

Historical notes record an initial full-template `security-extended` result of 31 findings (25 high, 6 medium) and a later 2026-09-30 result of 29 (23 high, 6 medium), dominated by filesystem-race reports in scripts and tests. As of 2026-09-30, no matching CodeQL Extended Actions run, SARIF/report artifact, or stored code-scanning alert could be retrieved from the current repository state. Treat the counts as unverified, do not claim individual findings were fixed or cleared, and rerun the extended workflow after it reaches the default branch so each current finding has retrievable evidence for triage. Keep the high-precision default workflow as the required PR check while reviewing each extended result; the dedicated weekly/manual workflow maintains the broader scan without making lower-confidence findings an automatic merge blocker.
