# Approved private artifacts

With [account chat](account-chat.md) enabled, a verified user can ask the agent to save a generic plain-text note or draft. Eve's `create_artifact` tool proposes a title and exact content and always pauses for approval. The chat shows the proposed input before the owner chooses **Approve** or **Cancel**. No artifact is written before approval. A denied call has no write.

The tool verifies the current and initiating account again after the wait. The application store also requires an active, matching conversation/session binding. It records one artifact per `(operationId, callId)` with a hash of the validated input. A replay with the same input returns the saved artifact; changed input under the same call ID conflicts. This bounds duplicate writes across Eve retries without relying on the browser to persist the result. Artifacts remain readable by their owner after conversation revocation, but new writes require an active binding.

Open `/artifacts` to read saved text, download it as a `.txt` file, delete the saved copy or navigate to its source conversation. The screen fetches pages with the current account token and clears its results when the account changes. Content is rendered as text, without executing HTML. The reference action stores text in the selected application database; it does not upload files or create public download links.

The same owner-only reads are available through `GET /api/v1/artifacts?limit=20&cursor=...`, `GET /api/v1/artifacts/ARTIFACT_UUID`, CLI `npm run app -- artifacts list|get`, MCP tools `artifacts_list` and `artifacts_get`, and `artifacts:///ARTIFACT_UUID` resources. `GET /api/v1/artifacts/ARTIFACT_UUID/download` returns a private `text/plain` attachment with a UUID-based filename. `DELETE /api/v1/artifacts/ARTIFACT_UUID`, `npm run app -- artifacts delete ARTIFACT_UUID` and MCP `artifacts_delete` erase the stored artifact fields; a second deletion or a foreign owner's deletion returns 404. All paths require a current registered-user bearer token and enabled account chat. The API has no artifact-create route: write authority comes from Eve's approved tool, not a client payload. The returned record includes the source operation/session/call IDs, title, content, `text/plain` type and creation time; do not treat these read surfaces as public sharing.

Deletion replaces the artifact's title and content with fixed markers, clears its content-derived hash and removes it from list, read and download results. The original operation/call ID remain as a tombstone, so the same approved call cannot recreate it on replay. Deleting an artifact does not erase text already present in the source conversation, stream projections, external exports or database backups; those have separate retention policies.

This reference does not implement uploads, artifact editing/versioning or an external side effect. The local browser contract uses real Supabase Auth, compiled Eve and a deterministic model to check approval, denial, owner isolation, export and deletion. Hosted workflow recovery and operational replay of an in-flight tool remain separate release checks.
