# Structured output reference

With [account chat](account-chat.md) enabled, `/structured` gives a verified user a separate form for turning source material into a title, summary and short list. The output is schema-validated by Eve and displayed as editable fields. The example is domain-neutral. Unsaved edits remain in the browser view; reloading restores the original generated result from the owner's durable stream projections. **Save draft** stores reviewed fields as a private application record. A saved draft reopens at `/structured?draft=RECORD_UUID` and later edits use the record's revision, so stale updates fail instead of overwriting another edit. Account records show an **Open structured draft** link.

The browser submits `{operationId,message,mode:"structured-record"}` to the same `/api/v1/conversations` broker used by chat. The broker chooses a fixed JSON Schema, includes it in the signed runtime creation body, and hashes that exact body for both the durable budget reservation and conversation reservation. The caller cannot supply a schema, model, provider endpoint or budget. A lost creation response is recovered through operation status without redispatching the turn. The form reads the owner-scoped `/events` projection after activation and requires both a validated `result.completed` payload and a completed run boundary before showing fields. If a completed run lacks its result, or the projection stays pending for a minute, the form attempts one bounded authenticated replay and rereads from the first projection cursor. A failed run, still-missing result, expired identity or rejected start appears as an error.

Before saving, the page URL retains only the operation ID (`/structured?id=UUID`), so a reload checks the existing owned operation. The generated result is also accessible through the projection REST, CLI and MCP reads documented in [conversation stream projections](conversation-projections.md). A **Recover result** control remains available if automatic replay fails; both paths replay a bounded range of Eve events into the projection table without starting another model turn. Recovery requires the source stream to remain available.

Saving creates a normal owner-scoped record whose `content` is a versioned JSON envelope: `{kind:"structured-draft",schemaVersion:1,sourceOperationId,value}`. The editor validates the envelope and confirms that the linked source operation belongs to the signed-in user before reopening it. The same record is available through the existing records REST, CLI and MCP CRUD surfaces; those generic surfaces can edit its raw content, so incompatible edits are rejected by the structured editor rather than silently coerced. Record creation is not idempotent: if a save response is lost, check account records before retrying. This flow still has no separate typed-draft API, field-level edit history, artifact side effect or guarantee that a projection identifies canonical model-history attempts.

The production model in `agent/agent.ts` is unchanged. The deterministic browser fixture uses Eve's `final_output` tool for schema-bound turns, matching the runtime protocol. The browser contract verifies automatic replay when the result projection is absent from the first read, fields, unsaved and saved reload behavior, revision updates, account-record reopening, CLI access, single dispatch after a lost response, rejection of caller-defined schemas and cross-account denial; the broker/budget tests verify a single signed body and request hash.
