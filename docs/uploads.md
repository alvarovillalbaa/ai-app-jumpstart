# Private upload foundation

The upload core is separate from the approval-gated artifact table. `lib/uploads/contract.ts` derives an opaque object key from the verified tenant and subject plus a server-generated UUID; a caller cannot choose a filesystem path. `lib/uploads/validation.ts` checks the real bytes, claimed media type and filename together, limits one file to 5 MiB, and copies the bytes before hashing them. The initial accepted classes are UTF-8 `.txt`, PNG, JPEG and PDF. HTML/SVG masquerading as text, malformed UTF-8, path-like names and mismatched signatures fail before storage. This is a format sanity check, **not** malware scanning or complete image/PDF parsing.

`lib/uploads/local.ts` provides private, immutable, owner-scoped storage for a single persistent host. It refuses a symlinked or group/world-accessible root, creates owner directories with mode `0700`, writes mode `0600` files, and publishes each object with an exclusive hard link after the temporary file is synced. Competing writes to one ID cannot replace a published object. Deleting or reading under another owner derives a different key. Keep the configured root on a persistent local volume, outside web-served directories, and back it up separately from the application database.

This foundation is **not an enabled upload feature**. There is no browser button, HTTP endpoint, account quota, metadata row, scanner, download link or cloud object adapter yet. Do not attach these bytes to Eve or serve them to a browser until the remaining lifecycle exists. The next implementation must add durable owner-scoped metadata and quota reservation across all four application databases, quarantine/scan state, private managed object storage, authenticated download and deletion, and cross-owner browser/provider tests. A Supabase deployment should use a [private bucket](https://supabase.com/docs/guides/storage/buckets/fundamentals) with [Storage RLS policies](https://supabase.com/docs/guides/storage/security/access-control); a backend service key bypasses those policies, so the application owner check remains necessary. Binary content needs an explicit scanning policy before release.
